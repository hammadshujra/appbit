# Appbit V2.5

V2.5 repairs the LiteAPKs transport/import regression introduced in V2.4 while retaining the V2.4 size and source-content scraper work.

## Import transport repair

- Restores Appbit's direct public-metadata request identity instead of forcing every raw request to impersonate a desktop browser.
- If LiteAPKs rejects a normal metadata request with HTTP 401/403 or returns a verification page, Appbit automatically retries the same public URL once through its installed Playwright Chromium browser.
- The Chromium path executes normal page JavaScript and keeps a short-lived browser session/cookies for the batch. It does not solve CAPTCHAs or bypass an interactive verification challenge.
- After the browser path succeeds, Appbit temporarily prefers that path for the rest of the import batch so it does not repeatedly hit a rejected raw endpoint.
- Auto Import no longer treats a blocked sitemap as proof that the whole site is unavailable; it falls back to the public listing crawler.
- One inaccessible app page no longer pauses an entire Auto Import or Update Center queue. That item is recorded as failed and the queue continues. Source-wide rate-limit/network/unavailable failures can still pause safely.

## Preserved V2.4 work

- App Size multi-source extraction and normalized byte storage remain enabled.
- LiteAPKs meta title, meta description, description-section text and full source/article content capture remain enabled.
- Existing database/collation safeguards and schema 128 are unchanged.

Visible version: **V2.5**.
