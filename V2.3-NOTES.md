# Appbit V2.3

This release is the complete file-size pipeline repair.

Size lookup order:
1. LiteAPKs primary app-page stat/label value.
2. Structured JSON-LD, metadata attributes, and hydration JSON size keys.
3. The exact LiteAPKs download/details page linked by that app.
4. HEAD / one-byte range metadata from an explicitly linked APK/XAPK/APKS file, using only the total response size.
5. A normal Playwright Chromium render of a page that was successfully fetched but injects Size client-side.

Important safeguards:
- `Total`, `Latest`, and unrelated captions cannot become an app size.
- A 206 response with only `Content-Length: 1` is not misreported as a one-byte app. The total must come from `Content-Range`.
- A download/details page with an explicit conflicting version cannot provide size/date for the current app version.
- HTTP 401/403/challenge responses are not bypassed.
- Existing valid database values are preserved when a refresh is partial.
- Schema 128 backfills valid raw size values already stored in source metadata.
- Update scans preserve current-version size/date until an update is explicitly applied.

Visible version: V2.3.
