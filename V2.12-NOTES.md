# Appbit V2.12

V2.12 repairs the Hostinger deployment transition that prevented V2.11 from replacing the last successful V2.10 build.

## What failed

- V2.10 built successfully but its SSR bundle still expected a loose `VERSION` file and therefore returned HTTP 500 on Hostinger.
- V2.11 removed that runtime read, but its new `pages/api/[[...path]].js` route mixed CommonJS loading with ESM exports inside a project declared as CommonJS. Hostinger's build parser rejected that route, so V2.11 never became the active deployment. The old V2.10 deployment therefore continued producing the `.next/server/VERSION` error.

## V2.12 repair

- The native Next API bridge is now `pages/api/[...path].mjs`, making its ESM module format explicit.
- `next.config.js` explicitly enables `.mjs` page extensions.
- The route uses normal ESM exports for Next API configuration and imports the existing CommonJS Appbit backend through Webpack interop.
- The production build still forces Webpack with `next build --webpack`.
- `npm run build` now runs a postbuild finalizer that also writes `VERSION` and `BUILD-INFO.json` into `.next/server`. Appbit no longer needs those files at runtime, but this compatibility copy prevents the exact Hostinger ENOENT failure even if an older compiled module is retained by the platform cache.
- Release identity remains bundled in `src/version.js` and the SSR shell.

Visible version: **V2.12**.
