# Appbit V2.4

V2.4 fixes the persistent App Size display/import path and adds LiteAPKs SEO/content capture.

## File-size repair

The remaining V2.3 failure was not only extraction. The API could already have a valid source size in `source_metadata_json`, but deliberately hid it when the source version differed from the managed/current database version. The detail page displays the source version, so hiding the source size in that state produced `App Size: Not reported` even when the source scan had found a valid size.

V2.4 now:
- displays a verified size from the same source metadata as the displayed source version;
- preserves the exact source label such as `17 MB` while also storing normalized bytes;
- reads LiteAPKs compact SIZE cards whether the value is above or below the label;
- checks raw HTML, JSON-LD/hydration data and size-related attributes;
- uses a normal desktop-browser request profile so the metadata request matches ordinary public-page markup more closely;
- renders the exact public app page with Chromium when SIZE/content is injected client-side;
- keeps the V2.3 source-provided download/details page and package-header fallbacks.

## Source SEO/content capture

Each app refresh/import also captures from the same LiteAPKs app page:
- page/meta title;
- meta description;
- description section text;
- full written article/source content, including headings, paragraphs and list items while excluding common navigation, ads, recommendations, screenshots, download controls, share blocks and comments.

The App detail page exposes these under **Source Content** and Copy All includes the SEO fields and written source content while continuing to omit technical IDs and the LiteAPKs source URL.

Visible version: **V2.4**.
