# Appbit V2.11

V2.11 repairs Hostinger managed Next.js runtime deployment.

- Removes runtime filesystem reads of `VERSION` / `BUILD-INFO.json` from compiled SSR code. Hostinger executes `.next/server` in a generated build directory, so those loose root files cannot be assumed to exist there.
- Adds a native Next.js catch-all API route that hosts the existing Appbit Express API stack under Hostinger's managed `next start` runtime.
- Starts Appbit database initialization and backup/background services from the native API runtime, rather than depending on the custom `server.js` process being selected by Hostinger.
- Adds a native Next.js sign-in page and mounts the existing login/logout handlers at `/api/auth/*`.
- Preserves public opaque R2 `/d/<token>` URLs by rewriting them internally to the streamed R2 download API.
- API requests now return JSON while the database is unavailable instead of attempting to render EJS files from the compiled Next server directory.
- Keeps the V2.10 Webpack build override: `next build --webpack`.

Visible version: **V2.11**.
