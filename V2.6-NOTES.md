# Appbit V2.6

V2.6 focuses only on the two unresolved scraper problems: core written-content boundaries and App Size reliability.

## Core content

Appbit now exports only:

- the actual Description/article section for the app;
- the app's Mod Info / Mod Information / Mod Features section when present;
- source Meta Title and Meta Description as separate fields.

The scraper explicitly stops/removes FAQ, Safety/Data Safety, Security Information, comments/reviews, recommended/related/similar apps, "You may also like", screenshots/gallery, download/install blocks, old/previous versions, permissions/privacy/changelog sections, navigation, footer, sharing/social and advertising text.

If the source has no explicit Description heading but has a recognized article-content container, only the opening written article content is retained until a Mod/FAQ/Safety/recommendation/download boundary. Old V2.4/V2.5 whole-article content is not carried forward after a fresh V2.6 refresh.

## Meta title and description

- Meta Title: document `<title>` first, then standard title / `og:title` / `twitter:title` metadata.
- Meta Description: standard `description`, `og:description`, `twitter:description`, then the source JSON-LD software description when present.
- Challenge/access-denied titles are rejected instead of being stored as SEO metadata.

## App Size

V2.6 prioritizes a typed size token from the visible app hero/front summary before generic page scanning. A candidate scores highest when it is near the Size label, Version, Google Play, rating, and Download APK/Download Now controls. Recommendation/FAQ/Safety/comments/description/history/footer regions are excluded from hero size selection.

The existing structured JSON, raw HTML, download/details-page, response-header and rendered-DOM fallbacks remain available.

A separate display/API bug is also fixed: a stale text value such as `Not reported` can no longer be selected ahead of a valid `fileSizeBytes` value already stored by the scraper.

## Import path

V2.5 Add APK / Auto Import recovery remains unchanged: a rejected direct public request can retry through the installed Chromium path, and one inaccessible app does not stop an entire batch. No CAPTCHA or access-control bypass is added.

Visible version: **V2.6**.
